# 首頁：市場強度與進場條件分離

## 已實作

- 首頁直接顯示目前符合條件的強勢前 10 檔。兩個排序共用候選名單：市場強度排序、進場條件排序。
- 後者按有效計畫、未核對、過期、核對中、等待、資料異常、衝突分組，同組維持原強勢名次；不宣稱預測勝率或獲利排名。
- 每檔顯示市場強度、24 小時漲幅、成交額、獨立的進場狀態與原因。有效計畫可直達進退場摘要，未核對／過期者可就地更新。
- 一鍵更新市場並核對前 10 檔，固定最多兩檔同時執行；不離開首頁，不建立真實訂單。名單以按下後更新完成的行情為準，逐檔失敗保留結果，其餘繼續。
- 沿用 generateAgentTradePlan 與 agentPlanStatus。過期、歷史、標的不符、快照缺漏等不能被首頁升格；現有記錄與前向模擬僅按原條件登錄。
- rankStrongRows 共用原選幣規則：上漲但低於 30%、成交額至少 1,000 萬 USDT、強度與流動性排序，最多 10 檔且不補足。
- 首頁只接受 90 秒內市場快照，以及 5 分鐘內已驗證的加密貨幣合約清單。行情失敗或過期時隱藏目前排名並提供重試。
- 原市場排行、事件框架與其他工具收進次要展開區；研究紀錄與成效入口保留。

## 驗證

新增五項測試：候選篩選與兩種排序的獨立性、過期／錯幣／歷史方案不得升格、行情與合約清單時效、唯一前十名與名單外方案隔離、批次併發及失敗保留。npm test 共 124 項 Node 測試及既有 smoke／架構／staging 檢查通過，靜態建置通過。

## 持續紀錄的實際缺口

目前前向追蹤位於 src/advice_forward_controller.js，仍依賴瀏覽器前景與連續公開行情。已檢視的 staging_server.py 對 /api/runtime/snapshot、/api/paper、/api/results 等路徑仍回傳 READ_ONLY_UPSTREAM_NOT_CONFIGURED。現行 GitHub Pages 為靜態介面，不是常駐收集服務；本次未新增全天候追蹤、付費資源或帳戶連線。

下一個獨立研究服務必須具備以下交付與驗收項目，才能稱為持續紀錄：

1. 指定常駐執行位置與可持久保存的磁碟；與 Production Execution V2 分離，不共用 canonical ledger。
2. 保存啟動後的新訊號、規則版本、原始事件時間／接收時間、逐筆成交序號、成本與狀態事件。
3. 單一寫入者與原子保存；重啟保留結案紀錄，未完成樣本標記中斷。斷線、資料缺漏與重啟區段不補算。
4. 唯讀快照輸出、健康狀態與資料新鮮度；前端未確認來源時保持目前的本機研究標示。
5. 以斷線、亂序、重複事件、磁碟寫入失敗與重啟測試驗收；只有資料完整的結案列入統計。

外部主機連線、持久磁碟與服務運行證據本次未取得，不能以首頁核對成功取代這些證據。
