# 獨立研究追蹤服務：設計與實作計畫

目的：手機關閉後仍由獨立主機觀察新分析，持久保存可追溯研究樣本。這不是 canonical ledger 或 Production Execution V2，不產生真實訂單。

## 選擇與邊界

選用 Node 24 + 內建 SQLite，重用目前三策略與前向判定純函式。相較重寫 Python 策略，可避免規則分歧；相較無磁碟的靜態／定時函式，可保持逐筆行情連線。既有 Railway 研究磁碟不得在未核對內容前覆蓋；可先在 Mac mini 或獨立容器使用新目錄運行。

- 每次啟動及新的小時執行一次前十檔篩選，逐檔建立行情觀察後分析；不補跑停機期間的排程。
- 使用公開 Binance 合約資料及 aggTrade 串流。歷史 K 線僅供目前已收盤訊號分析，不能變成過去的前向成交。
- 沿用 agentPlanStatus、normalizeForwardTick、tickContinuity、registerForwardAdvice、advanceForward、expireForward。既有時效、成本、門檻和最多 12 個活躍觀察限制不變；結案資料存入持久歷史，不套用瀏覽器的 500 筆總數限制，而受資料檔容量保護。
- 活躍樣本放入記憶體；完整結案／中斷紀錄存 SQLite。歷史樣本 ID 永久去重，同一訊號不可因重啟而重做。
- 單一寫入者由 SQLite 鎖資料庫的排他交易保護；程序死亡由 OS 釋放，不自動刪除他人的鎖。
- 事件與樣本變更放在同一交易，以 SHA-256 串鏈；活躍觀察逐筆記錄時間、序號與價格。啟動逐筆驗證鏈及樣本投影。雜湊不是外部簽章，不能證明未遭整庫重寫。
- 重啟／斷線／亂序／磁碟錯誤時 fail-closed。寫入失敗不發出成功狀態；不可寫時保留原檔，重啟後先標記 GAP。
- 只提供 GET /healthz、/readyz、/api/research/snapshot；不映射 /api/runtime/snapshot，不混用正式淨值。預設只監聽 localhost。
- 限制資料檔容量與保留原始資料；容量不足時停止，不能偷偷刪除或回補。無自動備份或高可用宣稱。

## 執行順序

1. 建立 SQLite journal、樣本投影、完整性核對、單寫入鎖及容量保護。
2. 實作獨立行情／分析協調器、世代隔離、排程、唯讀 HTTP、明確健康狀態。
3. 測試成交結案、重啟 GAP、歷史去重、亂序／重複／延遲、資料毀損、寫入失敗、雙寫入者及端點權限。
4. 新增專用容器與操作文件、獨立 CI；前端 build 不打包服務與資料。
5. 先完成測試與提交，再確認外部主機、磁碟、網路與持續觀察證據。未完成此步不得標示 24/7 已上線。

## 本輪不包含

正式帳本接入、正式 NAV／1.5% 風險驗證、手機推播、跨裝置 UI 串接、策略調參、資金費率／深度模型。保持 PAPER_ONLY、REAL_ORDER_LOCK、No Backfill。
