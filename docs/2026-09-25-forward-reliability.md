# 本機前向追蹤可靠性修正

## 本輪發現

修改前在已發布的 4b8c546 版本，UNIUSDT 公開逐筆行情實際接通。因此先前的連線逾時不能視為持續性資料源故障，也不能宣稱此修正解決了外部網路問題。

原控制器沒有區分建立連線與等待首筆合格行情，連線狀態上的最近時間只在整體狀態改變時更新；另將分頁鎖衝突等操作錯誤與紀錄損壞共用同一顯示條件，導致有效歷史成效與匯出被隱藏。

## 修正

- 記錄建連、首筆等待、連續行情、中斷、已停止各階段；公開顯示合格行情筆數、最後收到時間及觀測價。
- 每秒僅更新行情文字，不重繪整頁或複製整本紀錄；重複成交不增加合格筆數。
- 中斷後可手動重新檢查行情。舊 GAP 紀錄保留；新連線接通後須重新核對建議。以每個幣種的連線世代綁定非同步分析，舊連線上的分析和延遲回呼不能進入新觀察。
- 將資料錯誤與操作錯誤分離。只有經驗證的既有紀錄才能展示或匯出；損壞資料仍停止展示成效、禁止匯出且不覆蓋原文。寫入失敗回讀已保存內容，不宣稱未保存的事件已結案。
- 停止追蹤後保留本次頁面的最後行情觀測供查核，不持久化為交易資料。

## 驗證及邊界

新增測試涵蓋建立連線逾時、首筆等待逾時、行情文字更新、重連與舊分析隔離、延遲回呼、分頁鎖衝突保留有效成效、損壞儲存與恢復操作介面。整體 npm test 通過 109 項 Node 測試及既有 smoke／架構檢查，靜態建置通過。

策略、價格來源、十秒連續覆蓋門檻、成本及儲存格式維持原設定。PAPER_ONLY、REAL_ORDER_LOCK、No Backfill。未變更 canonical ledger、正式 NAV、Production Execution V2 或正式下單 runtime。

此模組仍限單一瀏覽器前景觀察。網路、分頁背景化與資料源可能中斷；此修正不提供全天候收集，也不產生平台總投報率。只有完整結案的有效研究樣本才納入成效。
